# 闲鱼渠道接入指南

飞鱼小铺提供可选的闲鱼渠道适配模块，用于把已获准的闲鱼商品、订单、支付、退款和发货流程接入小铺的订单与交付编排。该能力默认关闭，不包含任何平台凭据，也不代表安装后即可直接开展真实交易。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `flyfish-xianyu-api` | 渠道枚举与共享契约 |
| `flyfish-xianyu-app` | 平台 API、令牌、商品映射、订单、退款、消息和任务队列，默认端口 `10083` |
| `flyfish-common/common/bridge` | HMAC 请求签名、防重放和桥接开关 |
| `flyfish-auth` | 不透明渠道主体登录与已有账户关联 |
| `flyfish-shop` | 商品、订单、合同、交付和售后，不保存原始平台令牌 |
| `web/src/modules/xianyu` | 管理工作台、账户关联与受控领取页面 |

平台凭据和原始平台标识应只保存在渠道服务的安全环境中。主站通过短期不透明票据和签名桥接请求协作，前端不会接触平台 `accessToken`、`AppSecret` 或内部会话。

## 启用前准备

1. 获得闲鱼开放平台对应业务、接口、类目和商家的正式授权。
2. 准备独立 MariaDB、HTTPS 入口、备份、监控和最小网络访问范围。
3. 复制 `deploy/config/xianyu.env.example` 到部署环境之外的私有配置文件。
4. 生成 32 字节随机加密密钥和至少 32 字符的桥接密钥，分别备份，不写入 Git。
5. 先保持 `XIANYU_*_ENABLED=false`，完成只读查询和测试交易验收后再逐项启用。

配置中的应用密钥、卖家标识、商品编码和业务码必须来自实际平台控制台。不要把演示值用于生产，也不要用 Cookie 自动化或页面模拟操作替代官方接口。

## 本地构建

```bash
./mvnw -pl flyfish-xianyu-app,flyfish-auth/flyfish-auth-app,flyfish-shop/flyfish-shop-app -am test
./mvnw -pl flyfish-xianyu-app -am package -DskipTests

cd web
npm run test:xianyu
npm run build:xianyu
```

主站前端和闲鱼小程序候选包使用不同输出目录。需要同时构建时请串行执行 `npm run build` 与 `npm run build:xianyu`，避免共享资源同步相互覆盖。

## 部署

`flyfish-xianyu-app` 是可选的 Java 21 JVM 服务，不在默认 Docker Native 三服务体验栈中。systemd 示例位于 `deploy/systemd/flyfish-xianyu.service`。真实部署应按平台批准的网络拓扑放置服务，内部桥接接口不得直接暴露到公网。

典型发布顺序：

1. 部署数据库与渠道服务，所有交易开关保持关闭。
2. 配置应用和商家授权，验证签名、加密、白名单及只读查询。
3. 验证商品映射、订单幂等、退款冻结、交付任务恢复和平台发货回读。
4. 使用平台允许的测试商品完成付款、取消、退款和异常恢复。
5. 按商品和规格灰度开启新交易，持续保留关闭新交易但处理已有订单的能力。

## 安全要求

- AES-GCM 加密密钥、桥接密钥、平台 AppSecret 和商家令牌不得进入代码、日志或前端包。
- 支付与订单状态只接受经过签名、通过防重放校验的服务端投影；不信任客户端金额和状态。
- 退款中、部分退款或全额退款订单冻结新的交付和文件提取，已发生的离线权益需按合同人工处置。
- 结果不明的写操作进入 `UNKNOWN`，必须先查询平台并保存核查依据，不能直接重试。
- 新交易停用后仍需处理已付款订单、平台消息和售后，不应直接删除队列或账本。

平台接口与规则可能变化。上线前应以当前官方文档、控制台权限和真实联调结果为准。
